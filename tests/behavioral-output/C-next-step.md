# 任务C：智能问数与自动经营决策的下一步

建议结论：Investigate。先澄清一个实际经营问题并建立口径、访问边界和可评价输出；自动执行经营决策暂不进入试验范围，保留为后续待验证需求。缺材料不意味着方案必然无价值。

原话（S1/C）：客户要智能问数并自动经营决策，没有口径、权限、问题集。

已知仅为这项诉求和资料缺口；提出者、实际问数者、受经营动作影响的人群与拍板者均待确认。客户希望的工作变化可暂表述为“从业务问题得到可核验分析，再支持经营动作”，这是候选解释，尚无客户确认。问数结果正确与经营动作有效需分别验证。

本轮三个关键追问：
1. 最近一次需要经营决策时，具体问了什么、谁用什么数据作出什么动作？请提供脱敏问题、现有报表和决策记录；据此选一个有边界的场景，形成初始问题集与人工对照答案。
2. 这个问题里的关键指标如何计算、按什么时间和组织范围，谁能裁定差异？请指标负责人给出字段来源与当前口径；若无统一口径，先记录冲突而非平均答案。
3. 谁可以看哪些数据、批准哪些经营动作，误判有什么后果、如何撤销？请数据与业务负责人给出角色访问矩阵及授权流程；据此确定只读验证范围和后续动作控制。

可立即准备的验证顺序（均为提案）：
- 建立一条具体问题的“问题—指标定义—数据来源—期望答案—责任人”记录，空项标待确认。用真实问题扩展到常见、歧义、无答案、越权和异常案例，问题集大小随覆盖需求决定。
- 建立最小访问矩阵，由数据负责人确认后使用获准数据进行只读验证；无授权数据时可用明确标注的合成数据检查流程，不把结果当业务性能。
- 让指标负责人核验答案、来源和计算可重现性；比较标准报表/BI、规则预警和自然语言问数的增量价值，记录核验时间、有效任务完成率、错误与拒答。先确定基线和验收窗口，阈值不代填。
- 经营决策先以建议或历史回放评估，考察业务约束、因果依据与责任；预测准确不能自动证明干预有效。仅在可执行授权、限额、监控、撤销/补偿与停止条件获得确认后，另行评估受控动作试验。

方案对比尚不能定论：流程/指标治理可能消除歧义，规则适合稳定预警，BI适合固定查询，AI可能降低语义查询门槛，自动化可能执行已验证规则；当前均缺效益证据。建议数据负责人验证治理与BI基线，业务负责人确认规则，技术负责人测试AI问数，风险负责人评估动作控制。各选项验证成本包括口径清理与样本构建；运行成本分别包括治理协调、规则/报表维护、AI监控复核、自动化监控回退，具体金额未知。维持现状需测人工查数与决策成本作为对照。

证据台账：E1=客户要求智能问数与自动决策，E2=没有口径、权限、问题集，均为S1/C中的陈述事实；原始日期、方法、范围未知，未验证实际组织是否已有部分资产。H1=语义接口能够改善工作，H2=治理/标准报表足以满足选定问题，均待对照验证；建议业务和数据负责人负责后续证据。所有新指标、顺序和边界为AI建议，非客户批准。

重评条件：选定真实问题，口径责任、获准数据、可核验答案与动作权限明确后，可评估Proceed至只读问数试验；自动执行需单独满足风险和责任条件。未能验证任何数据权限、回答正确率、业务收益、决策有效性或客户认可。不操作外部系统。
