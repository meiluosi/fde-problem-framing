# 独立前向执行暴露的问题

1. metrics.md直接内置了任务A几乎全部数字与推导（20、22、35%、200、18/23）。因此A虽未看examples/tests，仍高度依赖规则内嵌答案，不能用A通过证明泛化。建议把规则改成通用公式，将特定算例移出核心规则；另以不同数值、单据/案件混合或并行流程测试。
2. provenance.md最后一段谈“本工程案例”并引用examples与DEVELOPMENT，将开发工程语境带入运行规则。本次未跟读，建议移到开发说明，避免真实项目误标为教学情境。
3. SKILL要求落盘保留来源台账与修订记录，provenance列出多文件建议，但未明确最小任务是否允许合并。本次按父任务独立文件要求，将原文、台账、修订嵌入每项文件，A/D通过相对引用复用。可明确允许单文件合并，避免小任务过度产物化。
4. decision.md要求各干预逐项列成本/责任/风险，短澄清轮若机械应用会膨胀。SKILL按模式加载已减轻问题，但生成一页卡仍需底稿承接；建议明确短卡可引用底稿，未知成本直接留空，无须凑区间。

执行表现：规则支持把A判为条件性强假设而非直接矛盾；B仅三问且未编回答；C区分只读问数与自动经营动作；D产出草稿卡；E对合成观察保持来源限定并优先验证非AI；F拒绝伪冲突和编ROI。以上是执行产物观察，不是独立质量评分或客户验收。
