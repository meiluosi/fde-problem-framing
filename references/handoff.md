# 与 fde-ramp 的衔接

已通过 GitHub 连接读取四份指定文件，版本指纹见 [upstream-sources.json](upstream-sources.json)。只记录接口与借鉴判断，不分发私有仓库全文。

| 上游输入 | 承接用途 | 本 Skill 新增 |
|---|---|---|
| activities.md | 选定活动、角色、触发与交接 | 针对真实个案验证耗时、异常、决策责任 |
| flow.md | 已有流程和问号 | 瓶颈、竞争根因、干预前后范围 |
| opportunities.md | 已选候选及其理由 | 检验具体问题与替代方案，不重复全局排名 |
| process-metrics.md | 耗时、频次、差错及成本上限 | 口径、覆盖、采用、复核成本、增量价值 |
| verification-list.md | 未决问题 | 与当前决策关联的最小验证 |
| sources.jsonl / corrections.md | 来源与已修正判断 | 保留原 ID、原文定位、修订轨迹 |

手动读取即可，无工具或仓库依赖。给输入记录路径、版本/哈希和读取日期。多批输入同名 S01 时命名空间化，例如 ramp-a:S01，并保存映射，禁止覆盖原编号。未提供的文件标“未提供”，不模拟导入成功。导入仅在新的场景目录引用/复制必要片段，不改原件。

上游的 AI 信号、四维评分是候选线索，不是本阶段证据闸门；不继承“命中两个信号即适用 AI”、数量式准备度门槛或行业平均数为客户基线。上游成本上限不等于能兑现的收益。客户材料与公开资料冲突时保留双方，按适用范围、时间、采集方法判断，不机械采用权威等级消解冲突。

## 下游：fde-demo 与 fde-pilot
- 建议结论为 Investigate 时，Demo 可作为执行最小验证的载体之一，不是绕过验证的捷径。fde-demo 只承接验证计划里的**一条**假设。
- 交给 fde-demo：最痛的一步（问题）、成功口径与基线、本期不做、验证计划 V*、失败样本。交给 fde-pilot：指标字典、本期不做、风险与退出。
- 回写：Demo 或试点推翻、修订的假设，以“回写建议”带前缀编号（`demo:`、`pilot:`）回来，由本 Skill 的修订流程处理，下游不直接改定义卡。
- 同名结论词含义不同：本 Skill 的 Proceed 表示所写范围的下一阶段（如做 Demo 或试点），不是 `demo:Proceed`（进入试点范围协商）或 `pilot:Proceed`（进入正式交付或扩大范围协商）。
