# 标准、制度与知识检索类问题的诊断

当场景是查标准/制度/知识库时读本文件。此Skill仍负责问题定义，不默认为用户开发问答产品。

以下用于界定客户任务和未来方案验收，不要求本 Skill 执行检索产品评测。先判断哪个环节存在可观察损失，再决定最小取证；不要把“人工读PDF”直接判为低效。

把四层任务拆开验收：①找到候选文件；②核验版本、效力/状态及适用范围；③取得有权限的正文并定位；④在上下文中解释和供人判断。前三层缺一时不能跳成“已正确回答条款”。有用的拒答可能是安全成功，但不是业务任务完成。

先问一个真实查询：谁、什么工程阶段、对象/井型/区域、现行还是历史时点、找文件还是要可执行依据。不要每题重复完整表单；只问影响答案的缺项。

来源等级与证据层级分开：官方目录只能证明其明确展示的元数据；只有已取得的正文才能支持条款号、引文与参数。页面导航包含“废止”不等于已废止；相近标准不等于替代；计划页不等于已实施；发布日期不等于实施日期。缓存/转载与官方记录冲突时记录访问时点与差异，不静默选择。无法取得全文时说明范围，给合法获取路径，不绕过访问限制。

“可参照”不能改写成无条件适用；题名相近不能跨行业、井型、区域或工程阶段套用。推荐性标签不能直接推定某项目毫无约束，合同、内部制度或其他要求是否引用需要另核；本Skill不作法律结论或代替专业责任人批准。

比较目录维护/同义词+全文搜索/状态规则与AI语义辅助，使用相同授权资料和同题对照；把整理成本、版本维护、复核与拒答纳入。先定义样本真实性与人类参考答案，再看排名/引用/净节时。失败、无正文和跨范围题不能从业务分母消失。条件不足时Investigate；已有证据证明简单办法足够时选择非AI方向，推进状态按阶段准备度另判。

已知文件但找不到条款时，优先正文定位和工况对照；不要把目录命中当作解决问题。记录PDF与印刷页码，跨页条款保留上下文。政府托管的企业标准仍是企业标准，正文可读不等于当前有效或本项目适用。使用 [答复模板](../templates/retrieval-answer.md)。
