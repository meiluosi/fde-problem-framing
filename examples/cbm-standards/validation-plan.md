# 验证计划与当前执行状态

| 验证 | 动作与对照 | 判定依据 | 当前状态 |
|---|---|---|---|
| V1 任务是否真实 | 用户评审review-for-user.md，按岗位纠正问题与查询时机 | 保留真实任务，删演示腔题；记录原话与修订 | 待用户评审 |
| V2 难在哪里 | 用最近任务回放，拆找文件/核版/取全文/找条款/解释/复核耗时 | 主要时间在哪、哪类错误会改变方案 | 未获一线日志 |
| V3 目录是否足够 | 同一题先用标准号/关键词+状态台账 | 目录即可完成的任务不算AI增益 | 已做公开元数据演练，非用户基线 |
| V4 全文与AI增量 | 相同授权资料，对比全文关键词+词表与AI；交叉安排顺序减少学习效应 | 标准/版本/适用/引用正确，净核验时间和失败均计入 | 无全文库，未执行 |
| V5 严重边界 | 旧版、计划页、跨井型、跨地区、缺正文、注入材料 | 不编条款，不自动判断适用，不用缓存冒充现时核验 | 纳入离线行为回归 |
| V6 用户评判稳定性 | 用户先给答案依据；有争议题请另一位相关岗位人员复核 | 分歧保留不强行多数决；按题族保留未见题 | 用户确认未完成 |

题集按四岗位×任务类型（找文件/核版/适用/定位条款/解释）分层，难题与无答案项纳入。当前十条目录是便利样本，不估行业召回率。不要将标准全文拆片随机分开发/测试造成同一条款泄漏；按标准族或新任务保留留出题。

每题记录：原问题、岗位/工程阶段/井型/地区/时间、现行或历史意图、可用资料权限、开始/结束及核验时长、标准号版本、范围判定、引用位置、拒答/升级理由、评审人与分歧。任务成功和条款成功分别计算：目录题不能充当条款题成功。

建议用户担任领域评审，实际业务决定仍由相应岗位负责人负责。没有发生现场操作，不设置虚构上线日期。拿到用户校准和全文后再评估 Proceed 至限定离线试点；若目录/全文搜索足够则 Non-AI；无法合法取全文且任务必须依赖正文则该部分 Stop-Defer。
